# 別マシンからの実画面巡回 手順書

**lifegence_i18n 0.1.0 ／ 2026年9月20日**

Frappe Cloud のように、対象サイト自身ではブラウザを動かせない環境で、実画面の巡回（経路 4）を別のマシンから行うための手順。

---

## 1. いつ使うか

実画面の巡回は、走査を実行するサイトの中で Playwright（ブラウザを動かす部品）を起動します。Frappe Cloud はサーバーに部品を追加できないため、本番サイトで走査を実行すると走査ログに `Screen : skipped — Playwright is not installed on this server` と出て、ほかの 3 経路だけが動きます。

そのときは、**Playwright を入れた別のマシン（以下「巡回マシン」）に本アプリを入れ、そこから本番サイトの画面を開いて読み取ります。** 結果は巡回マシン側の台帳に入ります。本番サイトの台帳へ自動で届ける仕組みは今回の範囲外です（巡回マシンの台帳から対象サイトへ訳を運ぶ手順は、利用マニュアルの取り込みと書き出しの節による）。

## 2. 巡回マシンに必要なもの

| 必要なもの | 内容 | 確認方法 |
|---|---|---|
| Frappe のベンチ | 対象サイトと同じ版（version-15 なら version-15） | `bench version` |
| 対象サイトと同じアプリ | 巡回マシンにも frappe / erpnext / 顧客アプリを、対象サイトと同じ版で入れる。回る画面の一覧と、データと画面の文字の見分けは巡回マシン側のサイトから取るため。**翻訳ファイルは揃えなくてよい**（第 6 章） | `bench version` の出力を対象サイトと突き合わせる |
| 本アプリ | `lifegence_i18n` を Playwright 付きで導入 | `pip install "lifegence_i18n[screen]"` のあと `playwright install chromium` |
| 対象サイトへの HTTPS 到達 | 巡回マシンから対象サイトの URL が開けること | ブラウザで開く |
| ロケール | 巡回マシンのサイトに、対象と同じロケール（例 ja-JP）と対象アプリの一覧 | Locale Profile を開く |

## 3. 対象サイト側の準備

1. **巡回用ユーザーを作る。** 閲覧専用で、**対象アプリの DocType に read 権限**があること。権限が無い画面は「開けなかった」に数えられ、測定されません（公開アプリの検証では、権限の足りないユーザーで 400 画面中 324 画面が開けませんでした）。
2. そのユーザーの**表示言語をロケールの言語に**する（ja-JP なら ja）。違うとログイン直後に巡回が止まり、走査ログに「The crawl user … reads the site in en, not ja」（走査を実行する側のユーザーが日本語なら「巡回用ユーザー … はサイトを en で表示しています」の訳）と出ます。
3. そのユーザーを**二段階認証とパスワード期限の対象外**にする。ログイン画面で止まります。
4. パスワードは**他で使っていないもの**にする。巡回マシンの設定に保存され、System Manager なら読み出せるためです。
5. **URL のホスト名が、対象サイトの名前（`sites/` 配下のディレクトリ名）と一致していること。** Frappe は `Host` ヘッダでサイトを決めるため、IP アドレスを指定すると「〈IP〉 does not exist」の 404 が返り、ログイン画面そのものが描かれません。巡回はログイン欄を探して待ち続け、`Page.fill: Timeout 30000ms exceeded` で終わります。`currentsite.txt` を置いても既定サイトには落ちません
6. **対象サイトが `/assets/` を配信できること。** デスクは JS を読み込んでから `/app` に遷移します。assets が 404 になる構成では、ログインは成功するのに遷移が完了せず、`wait_for_url` が 30 秒で切れて `Timeout 30000ms exceeded` になります。本番は nginx が配信しているので問題になりません。ローカル検証で自前のサイトを立てる場合は **`bench serve` を使う**こと（素の gunicorn は assets を配信しません）

    ```bash
    bench --site <対象サイト> serve --port 8100
    ```

## 4. 巡回マシン側の設定と実行

### 4-1. 設定（一度だけ）

多言語管理設定（`/app/i18n-settings`）の「実画面の巡回」の節。

| 項目 | 入れるもの |
|---|---|
| 巡回先のサイト URL（`screen_site_url`） | 対象サイトの URL。**https のみ**、かつ**ホスト名は対象サイト名と一致**させる（例 `https://<対象サイト>`）。IP アドレスは使えない（第 3 章 5） |
| 巡回用ユーザー（`screen_user`） | 第 3 章で作ったユーザー。空なら Administrator |
| 巡回用ユーザーのパスワード（`screen_password`） | そのパスワード |
| 1 回の走査で回る画面数の上限（`screen_max_screens`） | 既定 300。0 で全画面 |

スクリプトから設定する場合は上の括弧内が項目名です。別の名前で書き込んでも保存はされますが巡回には効かず、サイト既定の URL へ接続しにいって `ERR_CONNECTION_REFUSED` になります。

さらに、巡回マシンのサイトの `site_config.json` に次を足します。他サイトへの巡回は、この許可が無いと設定の保存時に止まります。

```json
"i18n_allow_remote_crawl": 1
```

### 4-2. 実行（2 通り）

**画面から**: ロケール（例 ja-JP）を開き、「測定対象」の「実画面（ブラウザ巡回）」にチェックを入れて「走査を実行」。ほかの 3 経路のあとに巡回が始まります。

**コマンドから**（画面巡回だけを回す）:

```bash
bench --site <巡回マシンのサイト> execute lifegence_i18n.scanner.screen.run --kwargs '{"locale": "ja-JP"}'
```

上限を変えるときは `{"locale": "ja-JP", "cap": 500}`。設定の上限は変えずに、その回だけ効きます。

所要時間は 1 画面 3 秒前後です。300 画面で 15 分前後、400 画面で 17 分前後でした。

### 4-3. 走査中に守ること

- **同じロケールの走査を重ねて始めない。** 実行中の走査があると、新しい走査は「まだ実行中です」と止まります。
- 巡回中は巡回マシンの走査記録が 25 画面ごとに「生きている」と記録します。15 分以上更新が無ければ落ちたとみなされ、次の走査が始められます。

## 5. 結果の見かた

走査記録（Translation Scan）のログに、次の行が出ます。

```
Screen: crawling https://<対象サイト> as i18n-crawler@…
Screen: judging by the site's own dictionary, 31842 translations for ja
Screen           :     12 new / 10 not wrapped on screen / 3 not delivered / 1006 confirmed — 398 screens in 982.2s (2 could not be opened)
Not delivered to the site (3): translated in the ledger, not served by the site
  'Zzz Export' on /app/data-export
Screen: could not open 2 of 400 — 2 x not available to the crawl user (no permission, or no such page)
Screens not opened: /app/authorization-control, /app/welcome-workspace
Ledger (screen): 12 new / 0 updated
Screens visited (398):
  /app/selling
  …
```

| 行 | 意味 | 見る場所 |
|---|---|---|
| `crawling … as …` | どのサイトを、誰として巡回したか | この行が無ければ巡回は始まっていない |
| `judging by the site's own dictionary, N translations for ja` | 対象サイトが巡回用ユーザーに配っている訳を N 件読み取り、それで判定した。`for` のあとが対象サイトの表示言語 | この行の代わりに `could not be read from the desk` が出たら、巡回マシンの辞書で判定している（第 6 章） |
| `N new` | 既存 3 経路が知らなかった文字列 | 翻訳台帳を「出所 ＝ 実画面」で絞る |
| `M not wrapped on screen` | 台帳に訳があり、**対象サイトもその訳を持っている**のに、画面は原文のまま | 指摘を「翻訳関数の未適用」で絞り、詳細が `screen:` で始まる行。訳では直らない |
| `L not delivered` | 台帳に訳があるが、**対象サイトはその訳を持っていない**（まだ配っていない、または古い訳のまま） | 次の行から始まる `Not delivered to the site` の一覧（最大 40 件）を見て、CSV を配布する（運用フロー ⑤） |
| `K confirmed` | 台帳の未訳を画面で確認した数 | — |
| `could not open` | 開けなかった画面の数と理由。次の `Screens not opened` が対象の画面（最大 40 件） | 権限不足なら第 3 章 1 を見直す |
| `Screens visited` | 回った画面の一覧（レコード名は DocType までに切る） | — |

**重要**: `not delivered` が大きいときは、対象サイトに翻訳ファイルが配られていない（または古い）状態です。「翻訳関数の未適用」ではないので、開発者に回さず、まず配布してください。

## 6. 判定に使う辞書は対象サイトのもの

画面の文字が「未訳か」「訳があるのに出ていないか」「訳はあるがまだ配っていないか」を判定する辞書は、**対象サイト自身**のものです。Frappe はログイン後の画面を出すとき、そのユーザーの言語の訳を全件まとめてブラウザに渡します（`frappe.boot.__messages`。version-15、16 とも同じ）。巡回はログイン直後にこれを 1 回読み取り、以後の判定に使います。走査ログの `judging by the site's own dictionary` の行がその記録です。

このため、**巡回マシンと対象サイトの翻訳ファイルを揃える必要はありません。** 巡回マシンの台帳（訳の正）と対象サイトの辞書（配布済みの訳）の 2 つで、画面の原文は次の 3 つに分かれます。

| 対象サイトの辞書 | 巡回マシンの台帳 | 判定 | 意味 |
|---|---|---|---|
| ある（台帳と同じ訳） | ある（承認済み） | `not wrapped on screen`（翻訳関数の未適用） | サイトは訳を持っているのに画面に出ない。コード側の修正 |
| 無い、または台帳と別の訳 | ある（承認済み） | `not delivered` | 訳はできているが、まだ対象サイトに配られていない（または古い訳のまま）。CSV を配布する |
| （問わない） | 無い | `confirmed`（未訳） | まだ誰も訳していない。訳を入れる。サイトが訳を配っていても、台帳に無ければ未訳として数える |

台帳の訳が下書きの行と、対象外の行は判定しません。

なお、対象サイトの表示言語もこのとき読み取ります。ロケールの言語と違えば、巡回はそこで止まり、走査ログに「reads the site in …, not …」と出ます（第 3 章 2）。

万一デスクの読み取りに失敗した場合（走査ログに `could not be read from the desk`）だけ、巡回マシンの辞書で判定します。このときは旧来どおり、両方の翻訳ファイルが揃っていないと `not wrapped` が過大に出ます。

## 7. 検証したこと

手元の Docker 環境で、version-15 のベンチを巡回マシン、同じコンテナ内の version-16 のサイト（別ポート）を対象サイトに見立てて巡回しました。ログイン、対象サイトの辞書の読み取り、画面の読み取り、権限の無い画面の検出、ログアウト、走査記録への保存まで動作しました（12 画面のうち 8 画面を読み、4 画面は巡回ユーザーの権限不足で「開けなかった」に分類）。

判定の辞書を巡回マシンのものから対象サイトのものに変えた効果は、この検証で数字として確認しました。日本語の無い version-16 を巡回したとき、変更前は 8 画面で 65 件が「訳があるのに原文（翻訳関数の未適用）」と数えられていましたが、変更後は未適用 2 件・未配布 62 件に分かれました（新規 14 件、確認済み 25 件、対象サイトの辞書は 511 件）。未配布 62 件は、巡回マシンの台帳には訳があるが version-16 のサイトが日本語を配っていないもので、これが本来の意味です。残った未適用 2 件は、対象サイト自身が訳を配っているのに画面が原文のものです（画面上のリンクとして描かれたワークスペース名 2 件、『Acme I18n Fixture』と『Localization』。対象サイトはそれぞれ『Acme I18n フィクスチャ』『多言語管理』を配っているのに、version-16 のリンクは原文のまま描かれていたもので、判定として正しい）。なお 9/20 の 65 件と今回の 64 件の差 1 件は、その後の台帳の変化（規則の追加や行の整理）によるものと考えられますが、9/20 の走査記録は残していないため確定はできません。同じサイトを巡回する通常の使い方（version-15 の 400 画面）では、変更の前後で結果は同じです（新規 6 件、翻訳関数の未適用 10 件、誤検出 0 件。未配布 0 件。新規・未適用の内訳も 1 件ずつ同一）。

**受け入れ時の実測（2026年9月27日、当社 version-15 環境）。** frappe 15.121.0 / erpnext 15.121.3 のベンチを巡回マシンとし、同じベンチのサイトを `bench serve` で立てて巡回しました。上限 300 画面に対し 205 画面を読み、95 画面は巡回ユーザーの権限不足で「開けなかった」に分類（会計・資産・銀行関連の DocType）。所要 2,244 秒（1 画面あたり約 11 秒。`bench serve` は単一プロセスのため本番より遅い）。

判定は対象サイト自身の辞書（ja の訳 22,701 件）で行いました。結果は新規 4 件・翻訳関数の未適用 7 件・未配布 0 件・確認済み 196 件です。

新規 4 件は、先に走らせた既存 3 経路の台帳 15,543 行（ソースコード 15,223／データベース 320）に存在しなかった文字列です。

| アプリ | 原文 |
|---|---|
| frappe | `Begin typing for results.` |
| frappe | `Compare` |
| clefincode_chat | `Check Status` |
| clefincode_chat | `Set Telegram Webhook` |

未適用 7 件には `/app/data-export` のボタン `Export`、`/app/security-settings` の説明文、`throw()` に文字列を直接渡している 3 件が含まれます。新規 4 件に誤検出（顧客データ・ブランド名・コード断片）はありませんでした。

この実測に至るまでに巡回が 3 回空振りしており、原因はいずれも設定と環境でした。第 3 章 5・6 と第 4-1 の項目名はそのときに確定したものです。

## 8. 分かっている制約

- 結果は巡回マシンの台帳に入る。対象サイトの台帳へ届けるのは範囲外（運用フロー参照）
- 回る画面の一覧（対象アプリの DocType・ワークスペース）と、データと画面の文字の見分け（マスターの名前、導入済みアプリ名）は巡回マシン側のサイトから取る。対象サイトと同じアプリ構成にしておく
- Frappe Cloud の Playwright 対応は今回の範囲外。Cloud 側で許可されれば、この手順書は不要になる
- 二段階認証やシングルサインオンだけのサイトには、巡回用ユーザーでログインできない
