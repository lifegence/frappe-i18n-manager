## 1. 結論

| 問い | 答え |

| 既存 3 経路で見つからない未訳は実在するか | **実在する。** 素の ERPNext（日本語）150 画面で 54 件。ワークスペースの見出し、ショートカットの件数書式、翻訳関数を通していないボタンなど |
| 誤検出は抑えられるか | **抑えられる。** 25 回の改善で、150 画面の誤検出 0（600 画面で約 3%）。正解が既知の合成アプリで再現率 100%（39/39）、誤報 0 |
| 再現性はあるか | **ある。** 同一条件で 2 回実行し、全 595 行が一致 |
| version-15 と 16 の両方で動くか | **動く。** 同じ除外規則のまま、v16 でも 150 画面で誤検出 0 |
| 残る不確実性 | 顧客環境（独自アプリ 5 本、大量の取引データ）での実測は未実施。精度調整は御見積書 備考 3 により範囲外 |
| 公開アプリでも動くか | **動く。** hrms・wiki・合成アプリを入れた v15 / v16 で 400 画面を巡回。この検証で見つかった 12 件の不具合はすべて修正済み（第 3-2 章） |

## 2. 方式

| 項目 | 内容 |
|---|---|
| ブラウザ自動化 | Playwright 1.63（Python）＋ Chromium headless。Apache-2.0 で AGPL-3.0 と両立。任意依存（`pip install "lifegence_i18n[screen]"`） |
| 実行場所 | Playwright の入った環境。Frappe Cloud では `Screen: skipped` と記録し他の経路は続行。別マシンからは `bench execute lifegence_i18n.scanner.screen.run` |
| ログイン | 設定（I18n Settings）の巡回用ユーザー。空欄なら Administrator。閲覧専用ユーザーを推奨（System Manager は保存済みパスワードを読み出せるため） |
| 巡回対象 | 公開ワークスペース → Single 設定画面 → 対象アプリの各 DocType の一覧・新規フォーム・既存レコード先頭 1 件。独自アプリ → frappe/erpnext の順。上限は設定（既定 300、0 で無制限）。custom DocType も含む |
| 取り出す文字 | 表示状態の DOM から: テキスト（インライン要素の連続を 1 単位）、placeholder、title（ツールチップ）、Select の option。**クリック操作はしない**（初版） |
| 台帳との照合 | 台帳を一括で読み、そのまま／空白・実体参照の正規化／記号除去／数値・括弧をプレースホルダに戻す／型（"You haven't created a {0} yet"）の順で照合。件数入り文字列は先頭の数値を `{0}` にした型で保存し、実文字列はログに残す |
| 結果の分類 | (1) 台帳に無い → origin=Screen で登録（除外規則を適用、略号は理由「略号・コード」・自動適用オフ）、(2) 訳があり、サイトも解決しているのに画面は原文 → 指摘「翻訳関数の未適用」に `screen: <URL> (<要素>)` を付けて登録、(3) 台帳の未訳を画面で確認 |
| 実行報告 | 走査ログに、件数・画面数・所要時間、正規化した文字列の一覧、**巡回した画面の URL 一覧**（レコード画面は `/app/<DocType>` までに切る） |

### 誤検出を防ぐ判断（「見た目」ではなく「置かれている場所」で判定する）

| 誤検出の原因 | 例 | 対策 |
|---|---|---|
| 顧客データ | 商品名、取引先名、倉庫名、勘定科目名 | 値の領域（フォームの値、一覧・グリッドの行、ツリー、グラフ、変更履歴、コード欄）を除外。マスタ 19 種のレコード名・導入済みアプリ名・URL のレコード名・ログインユーザー名を値扱い |
| 日本語の中の英字 | ERPNextの設定、POS設定 | CJK（半角カナ・全角英数を含む）を含む文字列は翻訳済み扱い。型だけ未訳のものは型照合で拾う |
| 型に値が入ったもの | Show アイテム List、0 Available、ID: 0ru39kd5oj、+ Add a Filter | 数値・ハッシュ・括弧・記号をプレースホルダに戻して照合。「ラベル: 値」は分解。プレースホルダだけの型は照合に使わない |
| ボタンのアクセスキー下線 | 「A」＋「sset Capitalization」 | インライン要素の連続を 1 単位として結合 |
| 訳文そのもの | GMail → Gmail | 表示文字が台帳のいずれかの訳文と一致すれば翻訳済み |
| 略号・キー操作・タイムゾーン | SKU、Ctrl+E、Asia/Tokyo | 略号は候補として理由付きで記録。キー操作表記は除外。タイムゾーンは tz データベースで判定（Yes/No を巻き込まない） |
| ラテン文字の対象言語 | クロアチア語の Srž、timesheets | 台帳の原文語彙と訳文語彙から英語らしさを判定。ダイアクリティクスは対象言語の証拠 |
| 全画面共通の文字 | ナビゲーションバー、検索欄 | 複数アプリの画面に出た文字は frappe に帰属（最初に見た顧客アプリに付けない） |
| 見つからない／権限なし画面、セッション切れ | 404、Not Permitted、/login への遷移 | Frappe のメッセージページの構造で判定（言語非依存）。セッション切れは残りを中断して理由を記録 |

## 3-2. 公開アプリでの検証（9/19〜20、回答 1-1 を受けて）

顧客のデータを預からない方針に合わせ、**公開アプリ hrms・wiki と、付録 A の型に沿った合成アプリ acme_i18n_fixture** を導入した環境で、version-15 と version-16 の両方を巡回しました。1 回あたり 400 画面です。

| 版 | 言語 | 開けた画面 | 新規検出 | 訳があるのに画面は原文 | 誤検出 |
|---|---|---|---|---|---|
| version-15 | ja | 398 / 400 | 6 | 10 | **0（0.0%）** |
| version-15 | hr | 398 / 400 | 6 | 8 | **0（0.0%）** |
| version-16 | ja | 398 / 400 | 38 | 2 | **0（0.0%）** |
| version-16 | hr | 398 / 400 | 12 | 3 | **0（0.0%）** |

**受入条件（未訳 1 件以上・誤検出 5% 以下）を 4 回とも満たしています。** 1 回あたり 1,000 件前後の文字列を台帳と照合したうえで、上表の件数が「新規」として残ったものです。開けなかった 2 画面は Administrator でも開けない画面（`/app/authorization-control`、`/app/welcome-workspace`）です。

同一条件での再実行で、指摘 10 件は完全に一致しました（再現性）。詳細と 1 件ずつの判定は別添の「公開アプリ巡回レポート」（20260920_公開アプリ巡回レポート.md）にあります。

この検証で、開発者ローカルの ERPNext だけでは出なかった不具合が 12 件見つかり、すべて修正しました。内訳は、長時間の巡回に耐える部分が 4 件、測定の取りこぼしが 3 件、誤検出が 5 件です。

| 見つかったこと | なぜ起きるか | 対応 |
|---|---|---|
| 400 画面の巡回後、最初のデータベース問い合わせが「サーバーが応答しない」で落ち、**20 分かけた走査の結果が全部消える** | 巡回中はデータベースに一切問い合わせないため、接続が切られる（version-16 で発生） | 25 画面ごとに接続を維持し、巡回後に接続を確認してから台帳へ書く |
| 同じロケールの走査が 2 つ同時に動き、データベースの排他制御で片方が強制終了 | 台帳は 1 サイトに 1 つ。同時に数千行を書くと衝突する | 実行中の走査があれば新しい走査を始めない。台帳への書き込みは 3 回まで再試行 |
| 走査が落ちると、その後しばらく新しい走査を始められない | 「実行中」のまま残った行と、動いている走査を区別できない | 巡回中の走査が 25 画面ごとに生存を記録し、15 分無音なら落ちたものとして扱う |
| 巡回中に走査自身の行の更新時刻がずれ、**最後の保存が失敗して報告が丸ごと消える** | 生存記録が行の列だけを書き換えていた | 文書経由で書き換え、最後の保存も競合に耐えるようにした |
| 台帳が 17,000 行になると、本アプリ自身の一覧画面が 30 秒で描画されず、その画面が測定されない | 読み込み完了の判定を「通信が止まること」に頼っていた | 画面が描画された時点で読む。通信が止まらなくても測定する |
| 日時項目の説明文が未訳として報告される | Frappe が説明文の末尾にサイトの時間帯（`Asia/Tokyo`）を足して表示する | 末尾の時間帯を取り除いてから台帳と照合する |
| 関連文書の件数と DocType 名が 1 つの文字列として報告される | フォーム下部の関連文書欄が「1 Wiki Page Revision」と並べて表示する | 件数は値として扱い、件数が付いた文字列も台帳の行に照合する |
| **説明文 1 件から 20 件の「新規未訳」が出る**（誤検出率 79%） | DocType の説明文は Markdown、HTML 項目は HTML で、Frappe はそれぞれを 1 つの文字列として訳す。画面では見出し・段落・箇条書きに分かれる | 台帳の行から各行を索引にし、画面の文字がそれに当たれば「その行の一部」として確認済み扱いにする |
| 巡回用ユーザーが読めない画面を「見た」に数えていた | 権限の無い DocType を開くと、Frappe はデスクを空のままダイアログで「見つかりません」と出す | 画面が描画されていなければ「開けなかった」に数え、走査ログに理由別の件数と対象を出す |
| 「0/4 steps completed」のような件数付きの表示が新規として出る | 件数の書き方が「0/4」「0%」「0 %」のときに件数として認識していなかった | 3 通りとも認識し、語句だけでも台帳を照合する |
| **経路 2 が、その版に無い列のせいで DocType 丸ごとを無言で除外していた**（既存不具合） | version-16 の `Module Onboarding` には `subtitle` も `success_message` も無い。問い合わせの失敗を握りつぶしていた | 実在する列だけを読み、読めなかった列を走査ログに 1 行残す。導入案内の題名 9 件が落ちていた |
| 設定画面の説明文が未訳として報告される | 台帳には改行タグ入りで入っているが、画面では 1 行に潰れて出るため照合できなかった（version-15 で 3 件、version-16 で 5 件） | マークアップを含む行は「潰れた形」でも索引に載せる |

**この 12 件は、素の ERPNext だけを 25 回巡回しても出ませんでした。**画面数が 150 から 400 に増えたこと、アプリが 3 本増えたこと、同時に別の走査が走ったことが条件でした。顧客環境（独自アプリ 5 本、大量のデータ）では、これらに近い条件が日常的に起こります。

## 4. 方式検証で分かった、既存経路への還元

| 発見 | 対応 |
|---|---|
| ワークスペースの見出し（content JSON）とショートカットの件数書式（format）は経路 2 で拾うべき | 経路 2 の対象に追加（別 PR、回答 3-5） |
| 「訳があるのに画面は原文」は反映検証（S-1）では Live と出て見えない | 指摘「翻訳関数の未適用」に `screen:` 付きで登録（回答 3-1） |
| 手で「対象外」にした行の理由を走査が消していた（既存不具合） | 修正（WP-2） |
| 台帳の (locale, text_hash) に一意制約が無い | 重複統合パッチ＋制約追加（回答 4-3） |

## 6. リスクと未了事項

- 顧客環境での実測（未訳 1 件以上・誤検出 5% 以下）は貴社にて実施（御見積書 備考 3、回答 1-1）
- 別マシンから Frappe Cloud のサイトを巡回した場合、結果は巡回側のサイトに記録される。対象サイトへ届ける仕組みは今回の範囲外
- クリックしないと出ない文言（保存時のエラー、ダイアログ）は初版では対象外。経路 3 が補う
- 日付選択部品の曜日は Frappe 本体に日本語辞書が無く、翻訳ファイルでは直らない
- 上限 0（全画面）で DocType が 700 を超えるサイトでは、裏側処理の打ち切りに注意（打ち切り時間は画面数から算出）
- 台帳が 17,000 行を超えたサイトで、本アプリ自身の台帳一覧画面が 30 秒以内に描画されず測定できない件は、第 3-2 章の 5 番のとおり修正済み（画面が描画された時点で読む）
- 巡回中に別の走査を始めることはできません（同時実行は台帳を壊すため）。定期実行と手動実行が重ならないようご注意ください
- **巡回で測れるのは、巡回用ユーザーが開ける画面だけです。** 閲覧専用ユーザーを使う場合は、測りたいアプリの DocType を読める権限を付けてください。開けなかった画面は走査ログに件数と対象が出ます

## 7. 添付

- 検証ログ（25 回分の条件・件数・変更点、自動判定の出力）は PR に添付
- 合成フィクスチャの正解表（`acme_fixture_truth.json`）は PR に添付。顧客の文字列は含まない
- 公開アプリ巡回レポート（別添）に、検出した文字列 1 件ずつの判定を記載
