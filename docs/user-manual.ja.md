## 0. はじめに読む（用語と読み進めかた）

### 3 行でいうと

1. ERPNext の画面には、日本語に訳されていない英語が残ります。標準の道具では、その全体像が測れません。
2. このアプリは **4 つの方法で英語を探し出し、1 行ずつの一覧（翻訳台帳）にまとめ、訳が実際に画面に出ているかまで確かめます。**
3. 訳す作業そのものは人が行います。このアプリは「どこを訳すべきか」「訳が届いているか」を教える計測器です。

### この文書に出てくる言葉

Frappe / ERPNext を初めて触る方向けに、最低限の言葉をここにまとめます。ここを読んでおけば、以降の章は前から順に読めます。

| 言葉 | これは何か |
|---|---|
| **Frappe** | 業務アプリを作るための土台（フレームワーク）。ERPNext もこのアプリも、この上で動きます |
| **ERPNext** | Frappe の上で動く業務システム。会計・在庫・販売・製造などが入っています |
| **本アプリ（多言語管理）** | Frappe の上で動くもう 1 つのアプリ。翻訳の状態を測ります |
| **DocType** | データの種類 1 つ分。入力画面とデータベースの表がセットになったもの。「翻訳台帳」「ロケール」などは、それぞれ 1 つの DocType です |
| **ワークスペース** | アプリのトップページ。本アプリのものは `/app/localization` |
| **ロケール** | 国・言語・通貨・日付や数値の書式をひとまとめにした設定。`ja-JP`（日本・日本語・円）など。**すべての操作の起点**です |
| **原文** | 翻訳のもとになる英語の文字列。Frappe では原文そのものが訳を引くときの鍵になります |
| **翻訳台帳** | 原文 1 つにつき 1 行の一覧。このアプリの中心です |
| **経路** | 未訳を探す方法。ソースコード／データベース／翻訳関数外／実画面 の 4 つ |
| **走査（スキャン）** | 経路を使って探す作業の 1 回分。実行のたびに記録が 1 件残ります |
| **網羅率** | 翻訳対象のうち、訳が付いている割合 |
| **反映検証** | 承認した訳が、実際に画面に出ているかの判定 |
| **指摘（課題）** | 検査で見つかった問題。未訳、プレースホルダの欠落、用語集違反など |
| **bench** | サーバー側で使うコマンド。**画面だけを使う方には不要です。** 本書では「サーバー担当者向け」と明記します |
| **Playwright** | ブラウザを自動で操作する道具。4 つ目の探し方（実画面の巡回）で使います |
| **Single** | 1 件しかない設定画面のこと（システム設定、多言語管理設定など）。Frappe の呼び方です |
| **フォールバック** | その言語に訳が無いとき、代わりに見に行く先。香港に訳が無ければ台湾を見る、など |
| **キャッシュ** | 表示を速くするために訳を一時的に覚えておく仕組み。ファイルを変えても画面が変わらない原因になることがあります |
| **文字列クラス** | その文字が何なのかの区分。UI 文字／ロール名／マスターデータ。網羅率に数えるのは UI 文字だけです |

### まず動かしてみる（30 分）

読む前に一度動かすと、以降の説明が早く入ります。

| 手順 | 操作 | 見るところ |
|---|---|---|
| 1 | ブラウザで `/app/localization` を開く | 「翻訳台帳の行数」「未訳の文字列」「未解決の問題」の 3 枚の数値カード |
| 2 | 「ロケール」→ `ja-JP` を開く | 上のほうに網羅率、下のほうに「測定対象」のチェック |
| 3 | 右上の「…」→「走査を実行」を押す | 走査の記録画面に切り替わり、状態が「実行中」になる |
| 4 | 数分待って再読み込み | 状態が「完了」。**「ログ」欄が結果のすべて**です（5 章） |
| 5 | 「翻訳台帳」を開き、状態「未訳」で絞る | 訳がまだ無い行の一覧。ここが日々の作業場です（9 章） |

この 6 手順が、このアプリの基本の一周です。あとは「訳を入れる」「サイトに反映する」「レビューを回す」が加わるだけです。

## 1. このアプリについて

### 何をするものか

**複数の国・言語・通貨で Frappe / ERPNext を運用するとき、多言語対応の状態を継続的に測り、抜けを検出します。**

翻訳そのものを行う道具ではありません。**どこが訳せていないかを機械的に洗い出し、訳の品質を検査し、成果物を生成する**ための台帳です。

### なぜ必要か

Frappe が標準で持つのは `Translation`（原文・訳文）と `Language` の 2 つだけです。次のものは存在しません。

- 翻訳対象の台帳（どの文字列が、どういう状態か）
- 用語集と、その遵守チェック
- 網羅率の測定
- プレースホルダ（`{0}` など）の破損検出

とくに Frappe が標準で用意している洗い出しの機能（サーバーで打つ `bench get-untranslated` というコマンド）は、**プログラムのソースコードの中の文字列しか見ません**。画面に出る文字のうちデータベースに保存されているもの（オンボーディング案内、ワークスペース、レポート名、通知の件名など）は永久に検出されません。

### 何をしないか

| 範囲外 | 補足 |
|---|---|
| 翻訳作業そのもの | 訳文の入力は人または外部の翻訳工程が行います |
| 機械翻訳・AI 翻訳の実行 | 将来の拡張候補です |
| 帳票（APITemplate）の多言語化 | 外部サービス側の対応が必要です |

**このアプリは実画面の目視確認を完全には代替しません。** 値打ちは「確認を不要にすること」ではなく、**確認すべき箇所を絞り込み、見落としの母数を減らすこと**にあります。

## 2. Frappe / ERPNext の多言語対応のしくみ

本アプリは Frappe の翻訳機構の**上で**動きます。何を補っているのかを掴んでいただくため、先に標準のしくみを説明します。

### 2-1. 訳はどこに置かれるか

3 か所あります。

| 置き場所 | 実体 | 誰のものか |
|---|---|---|
| PO / MO ファイル | `<app>/locale/<言語>.po` → `sites/assets/locale/<言語>/LC_MESSAGES/<app>.mo` | アプリ（v15 以降の標準） |
| CSV ファイル | `<app>/translations/<言語>.csv` | アプリ（旧方式。現在も読まれます） |
| Translation レコード | サイトのデータベース | そのサイト個別 |

### 2-2. 解決の順序

`_("Save")` が呼ばれると、Frappe は言語ごとに 1 つの辞書を組み立て、そこから引きます。積み上げの順序は次のとおりです。

1. 親言語のアプリ訳（導入済みアプリを順に、各アプリで CSV → MO）
2. その言語のアプリ訳
3. 親言語の Translation レコード
4. **その言語の Translation レコード**
5. 国名

**後に積んだものが勝ちます。** Translation レコードが最後にあるため、アプリ同梱の訳を確実に上書きできます。本アプリの「サイトへ反映」はここを使っています。

### 2-3. 親言語へのフォールバック

`zh-TW` のような派生言語は、まず親 `zh` を読み、その上に `zh-TW` を重ねます。`-` または `_` の前が親です。

有用な仕組みですが、**兄弟言語には効きません**。香港 `zh-HK` の親は `zh`（簡体字）であり、繁体字の `zh-TW` は兄弟なので参照されることがありません。本アプリの「フォールバック先」はこの穴を埋めるためのものです。

### 2-4. キーは原文そのもの

辞書のキーは原文の文字列そのままです。コンテキスト付きの場合は `原文:コンテキスト` になります。

**照合は完全一致です。** `"Save"` と `"Save "`（末尾に空白）は別のキーです。「訳を入れたのに画面に出ない」の典型的な原因がこれで、本アプリが空白不一致を検査している理由でもあります。

### 2-5. 何が翻訳対象になるか

`_()`（Python）と `__()`（JavaScript）を通った文字列です。加えて、コードを書かなくても次は自動的に対象になります。

- DocType のラベル・説明・Select の選択肢
- Page / Report の名前
- ワークフローの状態名
- カスタムフィールドのラベル

逆に、**`frappe.throw("...")` のように直接渡した文字列は、どの言語でも訳されません**。本アプリの「翻訳関数の未適用」はこれを検出します。

### 2-6. 標準の洗い出しコマンド

```bash
bench generate-pot-file --app <app>       # 原文を抽出して .pot を作る
bench create-po-file <言語> --app <app>   # 翻訳用の .po を作る
bench update-po-files --app <app>         # .pot の変更を .po に取り込む
bench compile-po-to-mo --app <app>        # .mo に変換（実際に読まれるのはこれ）
bench get-untranslated <言語> out.txt     # 未訳の一覧（CSV 方式）
```

**`generate-pot-file` も `get-untranslated` も、見るのはソースコードだけです。** データベースに入っている表示文字列は対象外で、これが本アプリのデータベース経路の存在理由です。

### 2-7. 表示言語の決まりかた

`User.language` → システム設定の言語 → `en` の順です。**ユーザーごとに違う言語で同じサイトを使えます。**

### 2-8. 日付と数値の書式

**書式は Language レコードが持ちます。** `date_format` / `time_format` / `number_format` / `first_day_of_the_week` が Language にあり、表示のたびにここが読まれます（無ければサイト既定）。本アプリの「サイトへ反映」が Language を書き換えるのはこのためです。

**通貨は言語から独立しています。** Currency ごとに書式と小数桁を持ち、金額はそちらで整形されます。日本語表示でも米ドル建ての伝票は米ドルの書式で出ます。**ロケールが言語と通貨を別の項目として持っているのは、標準がこの 2 つを分けているからです。**

### 2-9. キャッシュ

言語ごとの辞書は Redis に載ります。訳を変えたら `frappe.translate.clear_cache()` が要ります（「サイトへ反映」は自動で実行します）。

### 2-10. 標準に無いもの — 本アプリが補う範囲

| 論点 | Frappe 標準 | 本アプリ |
|---|---|---|
| 訳の置き場所 | ある（3 か所） | そのまま使う |
| 翻訳対象の台帳 | **無い** | Translation Entry |
| ソースコードの未訳 | 出せる | 同じ経路を台帳化 |
| DB 由来の未訳 | **出せない** | データベース経路 |
| 翻訳関数の未適用 | **出せない** | コードメッセージ経路 |
| 用語集と遵守チェック | **無い** | Glossary Term |
| 網羅率という数値 | **無い** | 2 種類の網羅率 |
| プレースホルダ・HTML・空白の検査 | **無い** | Translation Issue |
| 親言語フォールバック | ある | そのまま使う |
| 兄弟言語フォールバック | **無い** | フォールバック先 |
| 継承と固有訳の区別 | **無い** | 訳の出どころ（Own / Fallback / Inherited） |

**本アプリは Frappe の翻訳機構を置き換えません。** 訳の最終的な置き場所は標準の Translation レコードとアプリ同梱ファイルのままで、本アプリはその**手前**にある台帳・検査・測定を受け持ちます。アンインストールしても、反映済みの訳はサイトに残ります。

## 3. 画面の構成

ワークスペース：**`/app/localization`**（アプリ切替メニューでは「多言語管理」）

> `/apps/lifegence_i18n` という URL は存在しません。Frappe に `/apps/<アプリ名>` という経路自体がありません。

### DocType の一覧

本アプリが持つデータの種類です（DocType ＝ 入力画面とデータベースの表がセットになったもの。0 章の用語表を参照）。

| DocType | 日本語表示 | 役割 |
|---|---|---|
| Locale Profile | ロケール | 国・言語・通貨・表示形式の組。**すべての操作の起点** |
| Translation Entry | 翻訳台帳 | 原文・訳文・出所・状態を 1 行ずつ保持 |
| Glossary Term | 用語集 | ロケールごとの用語と、使ってはいけない訳語 |
| Translation Scan | 翻訳走査 | 走査 1 回分の記録 |
| Translation Issue | 指摘 | 検出した問題 |
| I18n Settings | 多言語管理設定 | 検出の共通設定（単一レコード） |

### 本アプリ自身の多言語対応

**このアプリの画面も、このアプリの流儀で作られています。**

- 項目名・ボタン名の原文は**英語**です
- 日本語は `lifegence_i18n/translations/ja.csv` で当てています
- 日本語以外の表示言語では**英語で表示されます**（日本語のままにはなりません）

他の言語を足すときは `translations/<言語コード>.csv` を追加します。台帳から「アプリ同梱 CSV」を書き出せば、そのまま置ける形式で出力されます。

> **同梱する語は選んでいます。** アプリの翻訳 CSV はサイト全体に効くため、`Status` や `Draft` のような一般語を入れると **ERPNext 全体の日本語表示を書き換えてしまいます**。frappe / erpnext がすでに訳している語は、そちらに委ねています（約 70 語）。核となる訳と競合させないという原則は、本アプリが検出する問題そのものです。

### ワークスペースの内容

- **数値カード** — 翻訳台帳の行数／未訳の文字列／未処理の指摘
- **ショートカット** — ロケール／翻訳台帳／指摘／用語集
- **レポート** — 網羅率（Localization Coverage）、除外の一覧（Localization Exclusions）、反映検証（Localization Delivery）

## 4. 準備

### 4-1. 共通設定（多言語管理設定）

`/app/i18n-settings`

| 項目 | 説明 | 初期値 |
|---|---|---|
| 原文の言語 | 翻訳元の言語コード | `en` |
| 未登録の言語を自動作成する | ロケール保存時に `Language` を作ります | オン |
| 未有効の通貨を自動で有効にする | ロケール保存時に `Currency` を有効化します | オン |
| 検出対象の最小文字数 | これより短い文字列は台帳に載せません | 2 |
| 除外規則（表） | 「この形の文字は訳さない」という規則の一覧。規則名・パターン（正規表現＝文字の形を表す書き方）・理由コード・自動適用・有効。旧「除外パターン」は非表示になり、この表に移りました | 命名シリーズ等 9 件（「略号」だけ自動適用オフ＝候補として理由を付けるだけ） |
| 英字のまま許容する語 | ブランド名・単位・略号。1 行 1 件 | Acme, ERPNext, SKU, kg など |
| **実画面の巡回**（節） | 経路 4 の設定。5-1 節を参照 | — |
| 巡回先のサイト URL | 巡回する先。空ならこのサイト自身。他サイトは https のみ、かつ site_config.json の `i18n_allow_remote_crawl` が必要 | 空 |
| 巡回用ユーザー | **閲覧専用のユーザーを作って指定することを推奨**。空欄なら Administrator。言語をロケールの言語にし、二段階認証やパスワード期限の対象外にする | 空（＝Administrator） |
| 巡回用ユーザーのパスワード | 暗号化して保存され、ログや成果物には出ません。ただし Frappe の仕様上、System Manager は保存済みパスワードを読み出せるため、**他で使っていないパスワード**にしてください | — |
| 1 回の走査で回る画面数の上限 | 上限に達したら止まります。**0 で上限なし**（全画面。約 2,000 画面で 1.8 時間） | 300（仮） |

![多言語管理設定の「実画面の巡回」](images/settings_screen_crawl.png)

**「英字のまま許容する語」は運用しながら育ててください。** 初期状態では「訳文の英字残り」の検出件数が多く出ます。ブランド名や略号を登録するたびに減ります。

### 4-2. ロケールの登録

`/app/locale-profile/new`

**必須は 4 つだけです。**

| 項目 | 例（日本） | 例（クロアチア） |
|---|---|---|
| ロケールコード | `ja-JP` | `hr-HR` |
| 国 | Japan | Croatia |
| 言語 | ja | hr |
| 通貨 | JPY | EUR |

ロケールコードは BCP-47 形式（`言語-国`）で入力します。これがレコード名になります。

**保存すると自動で次を行います。**

- `Language` レコードが無ければ作成し、無効なら有効化します
- `Currency` が無効なら有効化します
- 言語コードから **ラテン文字を使う言語かどうか** を判定します
- 国からタイムゾーンを引きます

#### 表示形式

| 項目 | 説明 |
|---|---|
| 日付形式 | 国によって異なります（日本 `yyyy-mm-dd` / 香港 `dd/mm/yyyy` / クロアチア `dd.mm.yyyy`） |
| 数値形式 | **クロアチアは `#.###,##`** です。小数点がカンマ、桁区切りがピリオドで、日本と逆になります |
| 小数桁数 | **円は 0 桁**です。補助単位を持たないためです |
| 週の開始曜日 | 日本・台湾・香港は日曜、クロアチアは月曜 |

#### フォールバック先

フォールバック＝**その言語に訳が無いとき、代わりに見に行く先**のことです。香港（繁体字）に訳が無ければ台湾（繁体字）を見る、といった指定をします。

**このロケール固有の訳が無いとき**に参照するロケールを指定します。

**香港（`zh-HK`）には台湾（`zh-TW`）を指定してください。** Frappe は言語コードの親（`zh` ＝簡体字）へ自動的に落とします。香港で必要なのは繁体字であり、`zh-TW` は親ではなく兄弟なので、**Frappe が自力でこの経路を通ることはありません。**

訳が決まる順序は次のとおりです。

| 順 | 参照先 | 台帳での表示 |
|---|---|---|
| 1 | その言語コード固有の訳 | `Own` |
| 2 | フォールバック先の台帳（連鎖する。上限 5 段） | `Fallback` |
| 3 | Frappe が現在解決している訳（親言語からの継承を含む） | `Inherited` |

**フォールバック先から取るのは、その先が「固有」または「フォールバック」として持っている訳だけです。** 台湾の台帳の大半は簡体字からの継承なので、それをそのまま香港へ渡すと、継承にすぎないものが固有の訳に化けてしまいます。

**走査の順序に注意してください。** 香港は台湾の台帳を読むため、台湾を先に測る必要があります。定期実行はこの順序を自動で組み立てます。

#### 測定対象

| 項目 | 説明 |
|---|---|
| ソースコードを走査する | `.py` / `.js` / `.json` 内の翻訳対象文字列 |
| データベースを走査する | 画面に出るがコードには無い文字列 |
| マスターデータを走査する | 品目グループ等の名前。顧客データなので既定オフ |
| ロール名を走査する | 既定オフ（二重計上を避ける） |
| 実画面（ブラウザ巡回） | 経路 4（5-1 節）。既定オフ |
| 翻訳関数の未適用を検出する | `frappe.throw` などに直接渡された文字列 |
| 対象アプリ | **空のときはサイトに導入済みの全アプリ**を対象にします |

**後から導入したカスタムアプリについて。** 対象アプリが空であれば、**次回の走査から自動的に対象になります**。設定変更は要りません。

対象アプリを明示している場合は、そのアプリは対象外のままです。**この状態は走査ログに `NOT MEASURED (N): ...` として毎回列挙されます。** 網羅率が高いまま、導入したアプリ 1 本がまるごと未訳という状態を黙って作らないためです。

> 対象になるのは **そのサイトに導入済みのアプリだけ**です。サーバーに置いてあるだけで、サイトに入れていないアプリは測れません（サーバー担当者向け: `bench install-app` を済ませたもの、という意味です）。

## 5. 測定する

ロケールを開き、**「走査を実行」** を押します。

バックグラウンドで実行され、走査レコードの画面に切り替わります。状態は **キュー追加済 → 実行中 → 完了** と変わり、完了すると画面が自動で更新されます。

> 参考：導入済み 23 アプリ・22,526 文字列で 35 秒程度です。

### 走査レコードの見かた

> 同じロケールの走査が動いているあいだは、もう一度「走査を実行」を押しても始まりません（「走査 … はまだ実行中です」と出ます）。前の走査が終わるのを待ってください。


| 項目 | 意味 |
|---|---|
| 総数／訳済／未訳／網羅率 | そのロケールの台帳全体の集計 |
| 新規登録 | 今回はじめて見つかった文字列 |
| 更新 | 現行の表示が変わった文字列 |
| 指摘 | 今回作られた指摘の件数 |
| アプリ×経路の内訳 | **アプリ×経路×文字列クラス**の表。ここがいちばん重要です |
| ログ | 経路ごとの件数と所要時間 |

### 台帳への書き込みかた

走査は台帳を **上書きしません**。

- はじめて見つかった文字列は新規に登録します
- **訳が無い行は、Frappe が現在解決している訳を取り込み**、状態を「承認済」にします
- **すでに訳が入っている行は触りません**

これにより、導入直後の台帳が空ではなく **現状を写した状態** から始まります。

### 5-1. 実画面の巡回（4 つ目の探し方）

**なぜ 4 つ目が要るのか。** これまでの 3 つ（ソースコード／データベース／翻訳関数外）は「訳すべき文字」を集める方法で、**画面そのものは一度も見ていません。** そのため次のようなものは、3 つのどれでも見つからず、画面には英語のまま残ります。

- ワークスペースの見出し（データの中に JSON という形式で埋まっているため）
- ショートカットの件数表示の書式（`{} Open` のような形）
- ボタンの文字のうち、翻訳のしくみを通していないもの

4 つ目は、**ブラウザを自動で動かしてサイトにログインし、画面を 1 枚ずつ開いて、そこに実際に表示されている文字を読み取ります。** 人が全画面を目で確認する代わりだと思ってください。

#### 使いかた

1. 多言語管理設定の「実画面の巡回」に、巡回用ユーザーとパスワードを入れる（4-1 節）
2. ロケールの「測定対象」で「実画面（ブラウザ巡回）」にチェックを入れる
3. 「走査を実行」を押す。ほかの 3 つが終わったあとに巡回が始まります

![ロケールの「測定対象」](images/locale_scan_screens.png)

#### どの画面を回るか

上から順に回り、設定した上限に達したら止まります。

1. 公開されているワークスペース（各アプリのトップページ）
2. 1 件しかない設定画面（システム設定、販売設定など。0 章の用語表の Single）
3. 対象アプリの各 DocType について、一覧・新規入力画面・既存レコード 1 件

**独自アプリを先に、frappe と ERPNext を最後に**回ります。上限で止まったときに、ほかの経路が見ていない画面が優先して見られているようにするためです。画面で手作りした公開ワークスペース（どのアプリにも属さないもの）は、さらにその前に回ります。

管理者が見られる画面は約 2,000 あり、1 画面あたり 3 秒強かかります。上限 300 なら 15 分ほどです。

#### 結果の読みかた

走査記録のログに、次の 1 行が出ます。

```
Screen: judging by the site's own dictionary, 31842 translations for ja
Screen           :     30 new / 4 not wrapped on screen / 2 not delivered / 294 confirmed — 40 screens in 138.4s
Not delivered to the site (2): translated in the ledger, not served by the site
  'Export' on /app/data-export
  'Quick Access' on /app/selling
Ledger (screen): 30 new / 0 updated
Screen normalised: '4 To Receive' -> '{0} To Receive'
Screens visited (40):
  /app/selling
  /app/item
  …
```

英語のままですが、意味はこうです。

| ログの言葉 | 意味 | 次にすること |
|---|---|---|
| `(N could not be opened)` | 行の末尾に出ることがあります。巡回用ユーザーが開けなかった画面の数 | 集計行の下に `Screen: could not open …`（理由別の件数）と `Screens not opened: …`（対象の画面）が出ます。権限不足なら巡回用ユーザーの権限を見直す |
| `30 new` | ほかの 3 つが知らなかった英語が 30 件 | 翻訳台帳を「出所 ＝ 実画面」で絞り、**訳を入れる**（9 章） |
| `judging by the site's own dictionary, … for ja` | 巡回したサイトが配っている訳（… 件）で判定した。`for` のあとが巡回用ユーザーの表示言語 | 別のマシンから巡回するときも、巡回した先のサイトの訳で判定されます（この節の末尾） |
| `4 not wrapped on screen` | 訳はあり、サイトもその訳を持っているのに、画面には英語が出ているものが 4 件 | 課題を種別「翻訳関数の未適用」で絞り、詳細が `screen:` で始まるものを見る。**訳では直りません。開発者にコードの修正を依頼**してください |
| `2 not delivered` | 台帳には承認済みの訳があるのに、サイトはその訳を持っていない（まだ配っていない、または古い訳のまま）ものが 2 件。集計行の次の行から `Not delivered to the site` の一覧（最大 40 件）が出ます | 訳を配布する（11 章）。開発者に回す必要はありません |
| `294 confirmed` | 台帳で未訳とされている文字を、画面でも英語だと確認できた数 | 特になし（測定の裏づけ） |
| `40 screens in 138.4s` | 40 画面を 138.4 秒で回った | 上限や所要時間の目安に |
| `Ledger (screen): 30 new` | そのうち台帳に新しく 30 行を追加した | — |
| `Screen normalised: …` | 件数入りの文字（「4 To Receive」）を型（「{0} To Receive」）に直して保存した記録 | — |
| `Screens visited (40):` 以下の行 | 実際に開いた画面の一覧。レコードを開いた画面は `/app/<DocType>` までで記録し、レコードの名前は残しません | 巡回の範囲を確認する |

ほかに出ることのある行です。

| 出る行 | 意味 |
|---|---|
| `(3 could not be opened)` が末尾に付く | 3 画面が開けなかった（権限が足りない、ページが存在しない など）。「巡回した画面」欄で確認できます |
| `Screen : not run — …` | 設定に不備があって巡回できなかった。**ほかの 3 つの結果はそのまま残ります** |
| `Screen : skipped — Playwright is not installed…` | このサーバーに Playwright が入っていない。同上 |
| `Claimed from site: 109 (acme_erp 87, erpnext 22)` | 持ち主が「site」（どのアプリのものか分からない）だった台帳の行 109 件を、今回の走査が特定したアプリに付け替えた。内訳はアプリごとの件数。実画面の巡回に限らず、どの走査でも出ることがあります |

![走査記録のログ](images/scan_log_screen.png)

新しく見つかった行は、翻訳台帳で「出所 ＝ 実画面」で絞れます。各行の「場所」に、どの画面で見つけたかが入ります（`/app/assets` など。レコードを開いた画面は `/app/<DocType>` までで記録し、レコードの名前は残しません）。

![翻訳台帳を「出所 = 実画面」で絞ったところ](images/ledger_origin_screen.png)

![指摘「翻訳関数の未適用」のうち、詳細が screen: で始まるもの](images/issues_rendered_untranslated.png)

#### 商品名や取引先名を「未訳」と間違えないしくみ

画面には、訳すべき文字（ボタンやラベル）と、訳してはいけない文字（商品名、取引先名、コード）が混ざって表示されます。このアプリは**文字の見た目ではなく、画面のどの場所にあるかで区別します。**

| データとして除外するもの | 例 |
|---|---|
| 入力欄の値、一覧の行、表の行、ツリー、グラフ、変更履歴 | 「Bath Bomb Sea Salt」「Acme Trading Co.」 |
| URL に入っているレコードの名前 | `/app/customer/Acme Trading Co.` の後半 |
| マスタ（会社・倉庫・勘定科目・品目グループなど）の名前 | 「Nagoya Depot」 |
| 導入済みアプリの名前、ログイン中のユーザーの氏名 | 「erpnext」「Crawler Sales」 |

また、**説明文や HTML 項目のように「1 つの文字列がまとめて訳される」もの**は、画面では見出し・段落・箇条書きに分かれて出ますが、分かれた 1 行ずつを新しい未訳として登録はしません（元の 1 つを訳せば画面全体が変わるためです）。

さらに、日本語が含まれる文字は訳し済みとみなします。命名シリーズなどの除外規則も、ほかの経路と同じものが適用されます。略号（SKU など全大文字の語）は理由「略号・コード」を候補として付けたうえで、誰かが確認するまで未訳に数え続けます。

#### 巡回できるのは「巡回用ユーザーが開ける画面」だけです（重要）

巡回は、指定したユーザーとしてログインして画面を開きます。**そのユーザーが読めない DocType の画面は開けません**（Frappe が「見つかりません」と出します）。閲覧専用のユーザーを作る場合は、**対象アプリの DocType に read 権限**を付けてください。無いと、その画面は「開けなかった」に数えられて測定されません。公開アプリでの検証では、権限の足りないユーザーで 400 画面中 324 画面が開けませんでした。走査ログには次のように出ます。

```
Screen: could not open 324 of 400 — 324 x not available to the crawl user (no permission, or no such page)
```

この行が出たら、巡回用ユーザーの権限を見直してください。権限を絞るほど、測れる画面は減ります。

#### 巡回用ユーザーについて（重要）

**閲覧専用の巡回用ユーザーを作ることを強く勧めます。** 空欄のままだと Administrator で巡回します。

理由は、Frappe の仕組みでは、システム管理者の権限を持つ人なら誰でも、ここに保存したパスワードを元の文字列のまま取り出せるからです。Administrator のパスワードを入れると、それが管理者全員に見える状態になります。

巡回用ユーザーに必要なのは、画面を**見る**権限だけです。あわせて次を満たしてください。

- 表示言語を、そのロケールの言語（日本語なら「日本語」）にする
- 二段階認証やパスワードの有効期限の対象にしない
- そのパスワードを他で使わない

このユーザー名で、ログイン履歴や閲覧履歴が残ります。あとから絞り込んで除外しやすくなるので、専用にしておく利点でもあります。

#### 拾わないもの

- **クリックしないと出ない文言**。初版は画面を開いた状態をそのまま読み、メニューやフィルタを開いたり、保存やダイアログの操作はしません（次版で検討）。保存時のエラーは「翻訳関数の未適用」の指摘が補います
- 日付を選ぶ部品の曜日（Frappe 本体に日本語の辞書が無いため、翻訳ファイルでは直りません）

#### サーバー担当者向け

経路 4 には Playwright（ブラウザを自動操作する道具）が必要です。サーバーで一度だけ次を実行します。

```bash
./env/bin/pip install playwright
./env/bin/playwright install --with-deps chromium   # 管理者権限が要ります
```

**Frappe Cloud のようにコマンドを打てない環境には入れられません。** その場合はログに `Screen: skipped` と出るだけで、ほかの 3 つは普通に動きます。別のマシン（Playwright を入れた開発機や検証サーバー）から、そのマシンの多言語管理設定に対象サイトの URL と認証情報を入れたうえで、次を実行します。

```bash
bench --site <サイト名> execute lifegence_i18n.scanner.screen.run --kwargs '{"locale": "ja-JP"}'
```

ただしこの形では、**結果は実行した側のサイトに記録されます。** 対象サイトの台帳には入りません。

判定に使う訳の辞書は、**巡回した先のサイト**が巡回用ユーザーに配っているものです（ログイン直後に 1 回読み取ります。ログの `judging by the site's own dictionary` の行）。実行した側と巡回先で翻訳ファイルが揃っていなくても構いません。台帳に訳があるのに巡回先が配っていないものは `not delivered` に数えられ、一覧がログに出ます。詳しい手順は[`remote-crawl.md`](remote-crawl.md)（日本語版は [`remote-crawl.ja.md`](remote-crawl.ja.md)）にあります。

巡回先の URL には決まりがあります。自分のサイト以外を指定する場合は https のみ、社内アドレスは不可、さらに `site_config.json` に `i18n_allow_remote_crawl` の設定が要ります。保存したパスワードをブラウザが送信する先なので、誤った宛先に送らないための制限です。

## 6. 結果を読む

`/app/query-report/Localization Coverage`（ワークスペースの「網羅率」）

ロケール × アプリ × 経路 × **文字列クラス**で、総数・訳済・未訳・網羅率が並びます。見出しの網羅率に数えるのは「UI 文字」の行だけです。「ロール名」「マスターデータ」の行は参考として別に出ます（既定ではオフなので通常は出ません）。

`/app/query-report/Localization Exclusions`（ワークスペースの「除外の一覧」）には、「対象外」とした文字列がロケール × アプリ × 理由 × 規則ごとに件数と例付きで並びます。顧客に「なぜ翻訳しないのか」を示す一覧です。

![除外の一覧](images/report_exclusions.png)

### 網羅率は 2 つあります

| 列 | 意味 |
|---|---|
| **表示上の網羅率** | 何らかの訳が出ている割合。**親言語からの継承を含みます** |
| **固有訳の網羅率** | そのロケール自身の訳（固有＋フォールバック）だけの割合 |
| 親言語からの継承 | 差の内訳 |

**この 2 つは大きく食い違うことがあります。**

| ロケール | 表示上 | 固有訳 |
|---|---:|---:|
| ja-JP | 88.4% | 88.4% |
| hr-HR | 73.4% | 73.4% |
| zh-TW | **71.7%** | **13.9%** |
| zh-HK | **71.7%** | **13.9%** |

繁体字圏で「71.7%」は実態を表していません。**残り 57.8% は簡体字が表示されています。** 中国語圏で判断に使えるのは固有訳の網羅率のほうです。

日本語やクロアチア語では親言語が無いため、2 つの値は一致します。

### 経路の違いを必ず見てください

参考環境（日本語）の実測値です。

| 経路 | アプリ | 網羅率 |
|---|---|---:|
| ソースコード | frappe | 96.5% |
| ソースコード | erpnext | 98.4% |
| **データベース** | **erpnext** | **13.6%** |
| **データベース** | **hrms** | **4.4%** |

**標準機能だけで測るとソースコードしか見えないため、「98% 完了」に見えます。** 画面に出る文字のうちデータベースに入っているものは一件も数えられていません。

## 7. 指摘に対応する

`/app/translation-issue`（ワークスペースの「課題」）

ロケール・種別・重大度・状態で絞り込めます。

### 種別の一覧

| 種別 | 重大度 | 意味 | 対処 |
|---|---|---|---|
| 未訳 | 中 | 訳が無い | 訳文を入れる |
| プレースホルダ不一致 | 高 | `{0}` や `%s` が欠落・増加 | **必ず直す。**実行時に値が出なくなります |
| HTML不一致 | 高 | タグが欠落・増加 | **必ず直す。**表示が崩れます |
| 用語集違反 | 低 | 用語集と違う訳語 | 確認して、必要なら一括変更 |
| 使用しない訳語 | 高 | 使わないと決めた語が入っている | 直す |
| 英字残り | 低 | 訳文に英字が残っている | 訳すか、許容語に登録する |
| 空白のため到達不能 | 中 | 原文の前後に空白があり、Python 側の翻訳関数から到達できない | 原文の空白を外したキーに直す |
| 翻訳関数の未適用 | 高 | `frappe.throw` などに直接渡されている | **ソースコードの修正が必要** |
| 翻訳関数の未適用（詳細が `screen:` で始まるもの） | 高 | 訳はサイトにあるのに実画面では英語のまま。描画するコードが翻訳関数を通していない | **ソースコードの修正が必要**（5-1 節） |

### 「翻訳関数の未適用」について

> **詳細が `screen:` で始まる行は、実画面の巡回が見つけたものです。**「サイトは訳を持っているのに、画面は原文のまま」という状態で、**Frappe 本体の制約により、台帳に訳を入れても画面には反映されません。**描画しているコード側（Frappe 本体、またはアプリのワークスペース描画）の修正が要ります。公開アプリの検証では、次の 3 通りが見つかりました。
>
> - ワークスペースの見出し（content JSON から、翻訳を通さずそのまま描画）
> - ボタンの文字（`__()` を通さずに設定）
> - フォームの項目名（英語のまま作られた定義がキャッシュに残っている）


これは **訳が足りないのではなく、翻訳ファイルが届かない場所にある**という指摘です。

```python
frappe.throw("Invalid Name")  # ← 訳は当たりません
frappe.throw(_("Invalid Name"))  # ← 訳が当たります
```

翻訳作業では絶対に解決しません。アプリのソース修正が要ります。f-string（`f"{x} updated"`）の場合は、`_("{0} updated").format(x)` の形に書き換える必要があります。

### 「空白のため到達不能」について

**Frappe は原文を完全一致で引きます。** 末尾に空白がある文字列は、空白の無い文字列とは別のキーです。訳が入っているのに画面に出ない、という現象の典型的な原因です。

### 「英字残り」について

**ラテン文字を使う言語では自動的に無効になります。** クロアチア語やドイツ語に対してこの検査をかけると全行が指摘されるためです。判定はロケールの「ラテン文字を使う言語」欄が行います。

### 指摘の状態

| 状態 | 意味 |
|---|---|
| 未対応 | 既定 |
| 対象外 | **この判断は次回の走査でも保持されます** |
| 対応済 | 次回の走査で作り直されます |

**指摘は導出データです。** 走査するたびに「対象外」以外は作り直されます。判断を残したいときは「対象外」にしてください。

## 8. 用語集を使う

`/app/glossary-term`

| 項目 | 説明 |
|---|---|
| ロケール | 用語集はロケールごとに持ちます |
| 用語（原文） | 例：`Customer` |
| 訳語 | 例：`得意先` |
| 訳さない | ブランド名など。**原文のまま出ているか**を検査します。さらに、原文全体がこの語だけの行（例：選択肢の「Acme ERP」）は、走査が「対象外（理由：ブランド・製品名）」として登録し、アプリ同梱 CSV には原文＝訳のまま出力します |
| 照合方法 | 単語（前後が英字でない）／部分一致 |
| 大文字小文字を区別する | 既定オン |
| 違反を指摘として記録する | オフにすると検査しません（参考情報として保持） |
| 使用しない訳語 | 1 行 1 件。含まれていたら重大度「高」で指摘します |

**「使用しない訳語」が効きます。** 例えば `Customer → 得意先` と決めたうえで、使用しない訳語に `顧客` を入れておくと、混在をすべて拾えます。

## 9. 訳を入れる・直す

### 9-0. 状態の流れ（先にこれをご理解ください）

```
未訳 ──訳文を入れる──▶ 下書き ──承認──▶ 承認済 ──「サイトへ反映」──▶ 画面に出る
                                レビュー表を取り込む──▶ 確認済 ──┘
```

**「サイトへ反映」が書き出すのは「承認済」と「確認済」だけです。「下書き」は反映されません。**

画面で訳を書き換えると状態は「下書き」になります。そのまま反映しても**その訳は画面に出ません**。反映時に下書きが残っている場合は、件数を明示して警告します。

> 反映しました
> 新規 12 件 / 更新 3 件
> **下書きのまま反映されなかった訳が 5 件あります。「動作 → 下書きを承認」をお使いください。**

**「動作 → 下書きを承認」**で、そのロケールの下書きを一括で承認済にできます（件数を確認するダイアログが出ます）。

下書きという段階をわざわざ設けているのは、**誰かが入力した訳と、誰かが合意した訳は別物**だからです。反映が勝手に承認を兼ねてしまうと、この区別が消えます。

### 9-1. 1 件ずつ直す

翻訳台帳（`/app/translation-entry`）をロケールで絞り、状態「未訳」で絞り込むのが基本の作業画面です。「指摘あり」で絞れば、訳はあるが問題のある行だけを拾えます。

行を開いて訳文を書き換えます。状態は自動で追随します。

- 訳文を入れると「未訳」→「下書き」
- 訳文を消すと「未訳」に戻ります

**まとめて直す場合**はリスト画面で複数行を選び、一括編集で状態を変更できます。訳文そのものの一括入力には次の 2 つが向いています。

### 9-2. CSV で一括投入する

翻訳台帳は Frappe 標準の **データインポート**に対応しています。

1. リスト画面 → メニュー → **インポート**
2. 更新（Update）を選び、`ID` と `訳文` の列を持つ CSV を読み込ませます
3. 取り込んだ行は「下書き」になります → **「動作 → 下書きを承認」**

外部の翻訳会社に大量に依頼する場合はこの経路が最短です。ID は「エクスポート → レビュー表 (CSV)」に含まれています。

### 9-3. 新しい文字列を手で追加する

走査で見つからない文字列（外部サービスの文言など）を管理したい場合は、翻訳台帳で新規作成します。**ロケール・原文・訳文**の 3 つが必要です。出所は「手動」になります。

**同じロケール・同じ原文・同じコンテキストの行は二重登録できません。** 既存行へのリンク付きでエラーになります。

### 9-4. 用語を一括で変更する

ロケールを開き、**「動作 → 用語の一括変更」**。

1. 変更前・変更後を入力し「影響範囲を確認」
2. **対象件数と、変更前後の対比が実行前に一覧で出ます**（先頭 200 件を表示）
3. 内容を確かめて「実行する」

**用語集を変えたときに何件動くのかが、実行前に見えます。**

## 10. レビューを回す

### 10-1. 書き出す

ロケールを開き、**「エクスポート → レビュー表 (CSV)」**。

| 列 | 内容 |
|---|---|
| ID | 台帳の行 ID。**編集しないでください** |
| アプリ／出所／状態 | 参考情報 |
| 原文／コンテキスト／訳文 | 現在の内容 |
| 指摘 | 検出済みの問題 |
| **修正案** | **記入欄** |
| **確認者コメント** | **記入欄** |

Excel で開けるよう BOM 付き UTF-8 で出力します。

### 10-2. 取り込む

**「インポートファイル → レビュー表 (CSV)」** で記入済みファイルを添付します。

- **「修正案」列に記入のある行だけ**を反映し、状態を「確認済」にします
- 空欄の行は変更しません。**途中まで記入した状態で戻しても安全です**
- ID がそのロケールに無い行は「対象外」として件数を報告します（別ロケールのシートを取り違えた場合に気づけます）

## 11. サイトに反映する

ロケールを開き、**「動作 → サイトへ反映」**。

次の 2 つを行います。

1. **表示形式を `Language` レコードに書き込みます**（日付形式・数値形式・週の開始曜日）。Frappe はここを読みます
2. **承認済・確認済の訳を `Translation` レコードとして書き込みます**

Frappe の解決順序は「アプリ同梱 CSV → アプリ MO → Translation レコード」で、**最後が最優先**です。したがってアプリ同梱の訳を上書きできます。

> **現在の表示と同じ訳はレコードを作りません。** 不要なレコードでサイトを膨らませないためです。

### 反映検証（訳が画面に届いているか）

走査のたびに、承認済・確認済の各行について「その訳が今この画面に出ているか」を判定し、台帳の「反映状況」とレポート「反映検証（Localization Delivery）」に出します。判定は、**ファイルをキャッシュを通さず読み直して**行います。ブラウザで見ると同じ「英語のまま」でも、直し方が違うためです。

| 反映状況 | 意味 | 直し方 |
|---|---|---|
| 反映済み（Live） | 画面にその訳が出ている | — |
| キャッシュ古い（Cache Stale） | ファイルにはその訳があるのに、サイトが古い内容を出している | `bench clear-cache` |
| 未反映（Not Deployed） | **どのアプリのファイルにもその訳が無い**（書き出していない、取り込んでいない、配置していない）。画面に古い訳や Frappe 標準の訳が出ていても、この状態です | 書き出して配置する |
| 上書き（Overridden） | どこかのアプリのファイルにはあるのに、後から読まれる別アプリのファイルか Translation レコードが勝っている | 勝っている側を探す |

**例**: 台帳で「Return Reason」の訳を「返品理由」から「返品の理由」に変えて承認した直後は、ファイルにはまだ「返品理由」しか無いので**未反映**です。CSV を書き出してアプリに置くと、キャッシュを消すまでは**キャッシュ古い**、消したあとは**反映済み**になります。

### アプリ同梱 CSV の書き出し

**「エクスポート → アプリ同梱 CSV」** でアプリを選ぶと、`<app>/translations/<lang>.csv` そのものの形式で出力します。アプリのリポジトリにそのまま置けます。

**訳文が原文と同一の行は除外します。** Frappe はどのみち原文に解決するため、差分が読みにくくなるだけだからです。ただし次の行は「訳さないと決めた」記録として出力します（以後の未訳報告に出なくなります）。

- 状態が「対象外」で、理由が「ブランド・製品名」または「略号・コード」の行
- 用語集で「訳さない語」に登録された語に一致する行

**列数**: 文脈が空の行は 2 列、文脈のある行は 3 列で書きます。既存の 2 列ファイルを書き出し直しても全行が書き換わりません。

**アプリのフォルダへ直接書き出す（サーバー担当者向け）**: ダイアログの「このベンチ上のアプリの translations フォルダにも書き出す」をオンにすると、ダウンロードに加えて、そのサーバーに置かれているアプリの `translations/<言語>.csv` にも同じ内容を書き込みます。開発者はそれをそのままリポジトリに登録できます。Frappe Cloud のようにサーバーのファイルに触れない環境では使えません（ダウンロードのみ）。

## 12. 国を追加する

**初期の 4 か国は固定ではありません。**

`/app/locale-profile/new` で 4 項目（ロケールコード・国・言語・通貨）を入力して保存し、「走査を実行」するだけです。

### 翻訳台帳の状態

| 値 | 表示 | 意味 |
|---|---|---|
| Untranslated | 未翻訳（frappe の訳） | 訳が無い |
| Draft | ドラフト（frappe の訳） | 訳を入れたが未確認 |
| Reviewed | 確認済 | レビューを通した |
| Approved | 承認済 | 確定。走査で取り込んだ既存訳もここ |
| Not Applicable | 特になし（erpnext の訳。本書では「対象外」と呼びます） | **集計から除外されます** |

### 対象外の理由コード

| 値 | 表示 | 何が付けるか |
|---|---|---|
| Naming Series | 命名シリーズ | 既定の除外規則（`SO-.YYYY.-` のような採番書式） |
| Acronym or Code | 略号・コード | 既定の除外規則「Acronym」。**自動適用がオフ**なので、理由は付きますが状態は「未翻訳」のままです。人が確認して「対象外」にします |
| Role Name | ロール名 | ロール名として台帳に入った行（文字列クラスも `Role Name`） |
| Master Data | マスターデータ | マスタのレコード名として入った行 |
| Brand or Product Name | ブランド・製品名 | 用語集で「訳さない」に登録した語と**原文全体が一致**する行 |
| Developer Note | 開発者向け | 既定の除外規則（URL、`a.b.c` 形式のパス、`eval:` で始まる式、`/api/` で始まるパス、`#f5f5f5` のような色コード） |
| Placeholder Only | プレースホルダのみ | 既定の除外規則（`{name}` や `<br>` のような、文の無い文字列） |
| Manual | 手動 | 人が手で設定した理由。**走査はこれを消しません** |

### 翻訳台帳の出所

| 値 | 表示 | 意味 |
|---|---|---|
| Source Code | ソースコード | `.py` / `.js` / `.json` から検出 |
| Database | データベース | サイトのレコードから検出 |
| Code Message | コードメッセージ | 翻訳関数を通っていない文字列 |
| Screen | 実画面 | ブラウザ巡回で検出（5-1 節）。「場所」に画面の住所 |
| Manual | マニュアル（erpnext の訳） | 手で追加した行 |

### 訳の出どころ（翻訳台帳）

| 値 | 意味 | 固有訳に数える |
|---|---|---|
| Own | その言語コード固有の訳 | ○ |
| Fallback | フォールバック先から採用 | ○ |
| Inherited | Frappe が親言語から継承したもの | × |
| （空） | 訳が無い | × |

### 走査の状態

キュー追加済 → 実行中 → 完了／失敗

失敗したときはログ欄にトレースが残ります。

## 15. うまくいかないとき

| 症状 | 原因と対処 |
|---|---|
| 走査が「キュー追加済」から進まない | 裏で処理を行う仕組み（ワーカー）が止まっています。サーバー担当者に確認を依頼してください（サーバー側で `bench start` またはワーカーの状態を見ます） |
| 網羅率が想定より高い | 対象アプリが絞られていないか、「データベースを走査する」がオフになっていないか確認してください |
| 訳を入れたのに画面に出ない | ① **状態が「下書き」のままではないか**（第 9-0 節）② 「サイトへ反映」を実行したか ③ **原文の前後の空白**が一致しているか |
| 表示言語を切り替えたのに台帳の訳が出ない | **「サイトへ反映」はロケールごとに実行が必要です。**台帳に訳があるだけでは画面は変わりません |
| 香港に切り替えたら簡体字が出る | 台湾を先に走査 → 香港を走査 →**香港で「サイトへ反映」**、の順で実行してください |
| 「英字残り」が大量に出る | 多言語管理設定の「英字のまま許容する語」にブランド名・略号を追加してください |
| ロケールを保存できない（言語が無い） | 多言語管理設定の「未登録の言語を自動作成する」がオフになっています |
| 同じ原文の行を追加できない | 同一ロケール・同一コンテキストの重複は登録できません。既存行を編集してください |

## 16. 正直に申し上げる点

- **「英字残り」は件数が多く、そのままでは使えません。** 許容語を育てる運用が前提です。指摘一覧であって、エラー一覧ではありません。
- **実画面の巡回は「開いた画面」しか見ません。** クリック後にしか出ない文言、権限で隠れている項目は拾いません。また Playwright の入った環境が必要です。
- **走査の対象は「サイトに導入済みのアプリ」です。** 導入していないアプリの文字列は測れません。
